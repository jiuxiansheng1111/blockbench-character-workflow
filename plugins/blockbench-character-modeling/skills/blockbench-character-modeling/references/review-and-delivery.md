# 视觉审阅与交付门槛

## 每轮必须亲自看的内容

| 检查 | 通过所需证据 | 常见失败 |
|---|---|---|
| 正面轮廓 | 露肤宽高和参考接近，左右颊被发框自然包住 | 整张方脸、额头过大、下颌横向阶梯 |
| 五官 | 眼白/虹膜/瞳孔可辨，眉眼距离自然，口居中 | 凸眼、双眉像斜杠、嘴如黑洞、眼睛过大过散 |
| 刘海 | 分点、扫向、缺口位置体现角色 | 贴瓦片、根部乱插、只有几块大额帘 |
| 顶冠/侧后 | 冠顶弧自然、后脑覆盖、长发终点正确 | 秃后脑、尖刺、齐尾墙、颊侧漏空 |
| 全身 | 头肩身裙腿协调，肩线平缓，脚落地 | 细长筷子身体、小裙、宽厚肩、长脖子 |
| 普通距离 | 缩小到游戏距离仍辨识角色与表情 | 近看细碎，远看只剩巨大眉/眼 |
| 对照 | 同视角灯光尺寸，附源文件 hash | 用新图美化、换相机掩盖问题 |
| 冻结部件 | 分组指纹与共用贴图依赖已核对 | 修脸时顺手拉伸全身、换掉已认可衣服 |

至少正、左、右、后三视方向（左右都看）、三分之四、头部近景和全身。遮挡严重的背面不能被一个正面截图替代。头部检查副本可以裁掉身体，但要记录删了什么；完整工程必须另有截图。

## 反馈处理

“上一版更好”意味着回到准确基线，保留已认可特征再小改；不是继续堆细节。遇到“眼睛怪”先核对位置、比例、形状、深度、颜色五项，而不是只换色。遇到“头发乱”先校正主发束路线与层级，再补数量。

一轮最多集中处理三类主要缺陷，保存修改前后和简报。不需要用户逐小步确认，但明显偏离参考时必须自己返工。多角色每人检查，不把同一张脸仅改发色称为完成。

## 交付清单

- 主 `.bbmodel` 与完整贴图；路径可搬迁，嵌入数据和外部依赖状态明确。
- 可重复生成/修改的脚本及具体运行方式（若采用脚本制作）。
- 参考来源、允许用途与未复制第三方资产的边界。
- 每轮简报、基线 SHA、冻结对照、审计 JSON、逐人修改说明。
- 最新全身总览、头部细节、正侧后、常规距离、前后对照。
- 遗留问题及真实验证阶段，不伪造量化相似度和多人认可。

`bbmodel_audit.py` 不进行渲染、碰撞、穿插、法线、世界空间包围盒或美术相似度判断；它不能代替真实编辑器/游戏。模型计数、资源哈希、构建成功都不是美术验收。
